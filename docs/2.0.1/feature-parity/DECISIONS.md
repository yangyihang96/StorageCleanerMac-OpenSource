# 竞品功能补齐（feature-parity）决定

## 2026-10-20（用户 2026-10-20：“请你把电脑中其他的清理软件也都逆向工程一下，然后和 CleanMyMac 进行对比。如果他们有的功能，CleanMyMac 没有，请你整合也做到我们的软件里去。如果对比一下相同的功能，其他软件有更优的解决方法，那就请你更新到我们的软件里去，让我们的软件成为最优、最好的。”）

证据和对照表：`~/Claude 好玩的/清理软件全功能对比-2026-10-20/对比与实现计划.md`（另见 `清理软件逆向-2026-10-19/`、`Mac清理与监控软件逆向-2026-10-15/`）。只借鉴功能和做法，不用对方的代码、素材、品牌和整句原文（同 D123、D141）。

临时编号 D-FP1–D-FP6，2.0.1 会话已同意对应 **D160–D165**（D153 归 2.0.1 会话的 Status Trio，D154–D159 归 CleanMyMac 界面会话），合并时由 2.0.1 会话写进主表 `docs/2.0.0/collab/DECISIONS.md`。

入口和路由由 CleanMyMac 界面会话接（它在把侧栏改成 CleanMyMac 的模块结构）：维护任务放“性能”，扩展放“应用”，聊天文件放“杂乱文件”，克隆合并和保留建议放重复文件管理器，进程说明放内存页和能耗页的进程行，损坏的偏好设置在垃圾清理的“系统垃圾”里。本组只交付服务、状态仓库和独立视图（`Views/Toolbox/`），不改 `ContentView`、`SidebarView`、`ReviewFilter`、`ModulePresentation` 和 `CareStudio*`。

## 不做，和记为差距的

- 需要 root 的维护任务（刷新 DNS、重建 Spotlight 索引、周期脚本、精简快照）：要么给 helper 加特权命令，要么用 osascript 提权，都超出现在的信任边界（L1–L8、D100）。如果要做，需要用户单独决定。
- 沿用 D100 不采纳表：安全粉碎、删语言包和二进制瘦身、purge、删 Time Machine 快照、主动推送和自动清理、Spotlight 找大文件、在线规则、自制恶意软件特征库、应用推荐页、删空文件夹和隐藏文件、强制结束进程。
- 更正对照表：清理排除目录我们已有（设置 › 扫描的排除列表，`ScanExclusionService`，扫描、文件分析和项目产物都遵守），不是差距。
- 仍是差距：最近使用项、Wi‑Fi 网络、应用权限审查（CleanMyMac 有）。卸载器的厂商级匹配（`ApplicationResourceFinder.isVendorGroup` 按 Team ID 匹配共享组容器）请 D151 的维护方核对会不会误选。
