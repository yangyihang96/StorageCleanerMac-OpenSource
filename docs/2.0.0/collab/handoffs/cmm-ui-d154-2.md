## 2. 改了什么

### 2.1 清理会话的 D160–D165 页面接进各模块（它们合进来时还没有入口）
- 三个页面各有一条路由（`ReviewFilter.extensions`、`.maintenance`、`.chatFiles`），侧栏仍高亮所属模块：扩展→应用管理、维护任务→性能优化、聊天文件→杂乱文件；“我的工具”各有一张卡；导航菜单不变（仍是 10 个模块）。
- `Features/Toolbox/ToolboxStores.swift`：每个 `ScanStore` 一套工具 Store（扩展、维护任务、聊天文件、克隆合并），用 ScanStore 的 `heavyWorkCoordinator`，结果卡和页面读的是同一份状态。
- **应用管理结果**加“扩展”卡（数量、已失效数），扫描应用时一并读取扩展清单（`pluginkit` 只读列举，D160）；夹具里不读。
- **性能优化结果**第一张是“维护任务”卡（建议运行几项）；各任务状态在用户点扫描、开始读取登录项时一并读取（只读探测，D161），页面出现时不自动读；夹具里不读。`CareStudioStartupResultsPage` 新增 `leadingTiles`。
- **杂乱文件**起始页多一个“聊天文件”小按钮（模板的 `relatedTools`，经新的环境动作 `careStudioOpenRoute` 打开页面）；结果卡片页里也有“聊天文件”卡。聊天文件只在打开它的页面时才读（要完全磁盘访问），卡片只显示上次读到的数量，不自动扫描别人的聊天目录。
- **重复文件**结果列表的工具栏加“合并为克隆…”（D163），只在最近一次扫描有内容已确认、且还不是克隆的组时出现。为此 `DuplicateFilesStore` 新增只读的 `exactGroups`（扫描完成时保存，重新扫描清空；从磁盘恢复的结果没有，要重新扫描才出现）。保留哪一份用清理会话的 `DuplicateKeeperSuggestion`；列表里用户自己点“保留”的选择还没有传给合并（合并前的确认面板会列出每组保留哪份）。
- **内存页**进程行加进程说明按钮（D164，没有说明的进程不显示），说明里的链接分别打开扩展、维护任务、空间地图（iOS 备份列在文件分析里）。

### 2.2 杂乱文件、安全防护改成 CleanMyMac 式结果卡片页
- **杂乱文件**（`CareStudioClutter.swift`）：重复文件扫描后先出结果卡片页——重复文件（逻辑重复量、组数、实际可空出的空间或“待核对”）、需要人工比较、相似照片、聊天文件，顶部“查看所有文件”“重新扫描”；每张卡只有“查看”，进入原来的审阅列表（列表工具栏多了“‹ 结果概览”）。没有任何一键删除；每组至少留一份、移到废纸篓可恢复照旧。从“我的工具”进相似照片仍直达审阅。
- **安全防护**（`CareStudioProtection.swift`）：浏览器隐私扫描后先出结果卡片页——浏览记录（条数、浏览器数）、敏感网站（默认折叠的条数）、Cookie 与其他数据、正在运行需先退出的浏览器；“查看”进入原来的记录列表（工具栏多了“‹ 结果概览”）。删除前备份、7 天内可恢复、运行中的浏览器要先退出等步骤都在列表里，不变。
- 两页都沿用 D141 做法：测试设 `careStudioClassicResults` 时直接显示原来的列表，原有的列表测试照旧。
