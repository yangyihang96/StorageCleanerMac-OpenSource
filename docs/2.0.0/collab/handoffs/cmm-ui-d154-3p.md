## 2. 改了什么

- **数字滚动计数**（新组件 `CareStudioCountingText`，`Views/CareStudio/CareStudioCountingText.swift`）：
  - 文字里的每个数都从 0 数到结果，写法与结果相同：小数位数、千位分隔符和小数点都不变（“0.0 GiB → 5.9 GiB”“1,234”“1.234,5 MB”）。过程中向下取整，不会超过结果，最后一帧就是原文字。不含数字的文字（“—”“未读取”）不变。
  - 先按结果的尺寸占位，计数画在上面。计数时周围什么都不动，窗口测试量到的尺寸也不变。
  - 时长和曲线用 `AppMotion.data`（0.7 秒，规范里“环、曲线、条和计数器”那一档）。打开“减少动态效果”时直接显示结果（这也是 data 档的规定）；截图和渲染测试（`featureDisablesLayoutAnimations`）同样直接显示结果。读屏只读结果。
  - 什么时候开始数由页面决定（`counted`）。开关放在页面上不会被重建的那一层，所以窗口变高变矮、在“整列/可滚动”或左右排布之间切换时，不会重新计数。
  - 经典（D70）页面已有的 `AnimatedByteCount` 不变：它只数字节，计数时宽度会变，状态在自己身上。
- **接在四处**：
  - 清理完成页（`CareStudioCleanupCompletedLayout`）的“X 已移到废纸篓”：进入页面 0.2 秒后开始数，正好在成功图弹出时（`CareStudioMotion.countAfterSuccess`）。
  - 内存释放结果页（`CareStudioMemoryResultPage`）的“+X”：同上。
  - 各结果页卡片的数值（`CareStudioTile`：智能扫描五张卡，以及应用、云盘、杂乱文件、防护、登录项、垃圾等结果页）：跟着卡片依次出现一起数，每张晚 0.05 秒，与卡片出现的错开相同。开关是网格的 `arrived`，卡片因窗口变化重建时也不会重数。
  - “我的活动”四张统计卡（`CareStudioStatCard`）：记录读完才开始数（读取期间是灰色占位）；以后刷新直接换成新数，不重数。原来数值上的 `.contentTransition(.numericText())` 已去掉，由计数代替；读记录那一次原本也没有动画。
  - 空间地图页没接（与 Disktree 第 2 期的约定，它合入之后再说）。
- **圆按钮**（`CareStudioActionButton`，所有页面共用这一个）：
  - 悬停：背后的光晕变亮（透明度 0.35 → 0.6，原来是 0.55），按钮面板微亮（亮度 +0.06）；不再放大（原来悬停会放大到 1.03）。
  - 按下：缩小到 0.95（原来 0.96），同时略压暗（亮度 −0.05）。
  - 禁用：悬停和按下都不反应（原来禁用时悬停也会放大）。
  - 打开“减少动态效果”：不缩放，按下只压暗；光晕变亮改为淡入淡出。
  - 曲线统一用 `AppMotion` 的 hover 档（0.16 秒 easeOut）和 press 档（弹簧，response 0.22、阻尼 0.7）。原来是单独写的 0.18 秒和 0.14 秒 easeOut，光晕是跳变。几个数值集中在 `CareStudioActionButtonLook`。

## 4. 测试

- 新增 `CareStudioCountingTests`（非窗口，5 个）：
  - 计数的写法：字节（一位小数）、KiB 整数、带“+”号、个数、千位分隔、德式“1.234,5”、“0.125”、两个数“3 / 12”；
  - 计数停在结果上，只增不减，不会比结果长，进度到 1 时就是原文字；
  - 不含数字的文字不变；
  - 用 ImageRenderer 渲染：计数开始和结束时的尺寸都与普通文字完全相同；开始时画的内容不同（0.0 GiB）；静止渲染画的就是结果；
  - 圆按钮在悬停、按下、减少动态效果、禁用四种情况下的反应。
- `CareStudioWindowReviewTests` 新增 `testCountsPlayInAWindowForReview`，只在设了截图目录时运行：在真实窗口里打开动画，每 50 毫秒存一帧，录清理完成页和智能扫描结果页。因此窗口用例从 626 个变成 627 个，不设截图目录时跳过 3 个（原来 2 个）。
- 原有测试的期望都没改。
