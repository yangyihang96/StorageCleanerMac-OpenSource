# 批次 2c 交接：重复文件扫描不读取 iCloud 仅云端占位文件

- 实现：Claude（主会话）　复核：全新上下文的 Claude 子代理（只读）
- 分支：`task/batch2c-dup-cloud`，基于 `a559084`

## 问题（N1，实机复现并定位）

已安装测试版做真实只读扫描时，点“取消”后 3 分钟以上停在“正在停止扫描”，期间占住重任务锁，其他扫描都开不了。`sample` 三次（约 50 秒）显示扫描线程一直在 `DuplicateFileScanner.quickFingerprint → readExactly → read()`；`lsof` 显示当时读的文件带 `compressed,dataless`（iCloud 仅云端占位，约 75 KB）。读取占位文件会让系统在 `read()` 里同步下载，取消和时间预算都只在文件之间检查，打断不了；“只读扫描”也因此触发了下载。

## 改动

| 项 | 内容 |
|---|---|
| 发现阶段 | 用 `lstat` 的 `st_flags & SF_DATALESS` 识别占位文件并跳过，不读内容；按根目录累计个数和字节数，只保留最多 20 条示例路径 |
| 读取兜底 | 扫描线程运行期间禁止物化占位文件（`IOPOL_TYPE_VFS_MATERIALIZE_DATALESS_FILES = OFF`），结束恢复原值；目录列举的后台线程同样处理，仅在云端的目录记为“仅在云端” |
| 续扫 | 比对前再检查一次全部候选（含续扫索引带来的），变成占位的计入“仅在云端”，不再静默丢弃 |
| 界面 | 扫描覆盖报告每个根目录显示“其中 N 个文件仅在云端，未下载比对”，并给出汇总说明（信息级，非警告）；结果为空且有云端文件时，标题改为“已比对的文件中未发现内容相同文件”，并附说明 |
| 结果口径 | 有云端文件未比对时结果为“部分完成” |

## 验证

- 修复版用同一真实数据跑完整功能审计：重复文件约 11 秒完成、53 组结果，未卡住；同一轮里智能扫描、安全清理、开发工具三项真实扫描都走到结果页（此前被 N1 挡住）。
- 新增测试：占位文件不读取且结果为部分完成；扫描期间线程策略为 OFF、结束后恢复为扫描前的 ON；25 个云端文件计数准确且只保留 20 条示例；续扫候选变成占位后计入而不丢失。
- Debug 全量（复核修改前）：3103 项／跳过 22／0 失败。

## 复核意见与处理

结论“需修改后合并”，无 P0。
- P1：新文案在界面上显示不出来（只渲染根目录级原因，`skippedPaths` 和 `.partial` 没有界面消费者）。已处理，见上表“界面”。
- P2 已处理：续扫候选兜底；策略测试改为能抓住回归（删掉 OFF 设置会失败）；示例路径设上限；目录列举线程同样禁止物化；只在读取策略成功时才恢复。
- P2 未处理：只看元数据的“同名/同大小/同类型”候选规则也排除了占位文件（覆盖面比以前小，已在说明里写“未比对”）；每个文件两次 `lstat`（性能影响小）；占位判定与其他模块（`isUbiquitousItem`）口径不同，后续抽共享函数。

## 兼容性

新的跳过原因 `cloudPlaceholder` 与新增的计数字段：新版读旧数据没有问题；旧测试版读到新数据会解码失败，续扫索引被丢弃、上次结果不恢复（只影响测试版数据目录，正式版目录独立）。
