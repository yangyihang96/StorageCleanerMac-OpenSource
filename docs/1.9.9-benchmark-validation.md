## 3. 状态机与失败语义

当前状态机包含：

`idle → preflighting → ready/preparing → warmingUp → calibrating/running → validating → aggregating → scoring → persisting → completed`

以及 `cancelling/cancelled` 和 `failed`。非法跳转、重复运行、取消后的迟到进度和持久化竞态由定向测试覆盖。

V7 现在使用结构化 `timedOut` 失败，保留 phase/category/workload 上下文。标准政策为 preflight 30 秒、普通 workload 的声明上限 + 60 秒、sustained 目标时长 + 30 秒、持久化/回读 30 秒。CPU、GPU、Memory、Storage 和 Display 的共享 `runSubtest` 另有 120 秒独立 watchdog；超时记录保留精确 workload ID 和 repetition。超时或取消后关闭迟到 progress；外层任务和全部内层迟到 kernel 均结束前，HeavyWork quarantine 不会释放。迟到成功不得覆盖 terminal timeout，也不得进入历史或本机最佳。Sustained 继续由独立顶层时限覆盖，不声称系统可以强制终止不响应取消的底层硬件调用。

raw kernel 失败走同一结构化持久化路径：失败记录为 `BenchmarkV7WorkloadFailureRecord(category, workloadID, reason)`，保留最后真实 progress context；`reason` 仅来自 safe classifier，不持久化 reflection 或 raw path。测试注入 `$HOME/private/secret-token`，并断言 `runtimeWarnings` 与 JSON 均不含该敏感路径。preflight timeout 的稳定 warning 为 `v7 workload failure: timed out phase=preflighting category=unknown`。

Preflight 当前读取：

- 电源来源和电池百分比；
- Low Power Mode；
- thermal state；
- 两次背景负载；
- 可用内存；
- 存储卷、只读状态和可用空间；
- 当前显示器描述。

本轮修复了一个会让“失败”看起来像“成功”的生产闭环缺口：`MacBenchmarkStore.finishV7` 在本地 history `save` 直接抛错时原先只更新失败状态，却仍将无 `failure` 的 terminal result 暴露给 latest projection，可能显示未落盘分数。现在保存失败立即转换为 `.persistenceFailed` 诊断记录，清除 Core/Experience 分数，并阻止 `latest`/本机最佳投影把它当作成功；该路径由 `testHistorySaveFailureDoesNotPublishAnUnsavedCompletedScore` 覆盖。该修复只改变本地保存失败语义，不伪造或重算任何分数。

严重/critical thermal 会硬阻断类别；存储卷只读或空间不足只硬阻断 Storage。强制继续不能绕过 hard block。

生产 workload runner 现在在每个 CPU、GPU、Memory、Storage 和 Display 子项边界保留 `category + workloadID + actionable reason`。后续类别失败时，之前已经完成并通过校验的 metrics 随 `partiallyCompleted` 结果一同持久化，不再被压成空数组；旧 v7 JSON 缺少新增可选字段时仍可解码。Sustained 后置失败同样保留前五类结果。该合同有受控测试证据，但本轮没有为证明它而故意让真实长跑失败。

## 4. 分数、置信度和“本机最佳”

有效 `BenchmarkV7Result` 保存：

- 独立 history record ID 和 session；
- plan/workload/scoring 版本；
- preflight 和非敏感设备环境；
- 每个 metric 的原始样本与统计；
- Core / Experience 分数；
- sustained 原始窗口；
- 置信度、运行时警告、完成时间或失败原因。

只有同时满足以下条件的结果才是当前官方结果：

- 匹配当前 official plan/workload version；
- 无失败且有完成时间；
- Core、Experience、Sustained 全部完整；
- metrics 非空且全部有效。

进入“本机最佳”还要求 AC power、Low Power Mode 关闭、thermal nominal，且置信度不是 low。此前 Store 的最佳值归约只复核 comparable 和 confidence，未实际调用完整 ranking predicate；现已在总体与分项共用的 `bestV7Result` 根入口同时要求 `isCurrentOfficialRankingEligible`。新增测试证明 battery、Low Power Mode 和 non-nominal thermal 的高分记录都不会覆盖合格成绩。旧算法版本不会直接和当前版本混排。

截至本次交接，用户产品 history 没有同时满足当前 official plan、完整 metrics、完成状态和非 low confidence 的可确认有效官方成绩；因此不发布新的 Core/Experience 分数，也不更新“本机最佳”。

三次结果是 opt-in 本地 JSON 采集，没有写入产品历史 Store；而且该采集只运行 standard 的 CPU/GPU/Memory/Storage/Display，不含 `OfficialBenchmarkPlan.current` 追加的 sustained 阶段。其后完成的隔离产品流程采集包含 Sustained，但仍未写入用户产品 history；且结果 confidence 为 low，最终 Store 会保留它作为最新/历史诊断记录，但不会纳入总体或分项“本机最佳”。

- 官方完整流程遇到 Storage 硬阻断会在启动 workload 前失败，不再通过“缺少被阻断类别也算完成”的合同。
- 不响应取消的 kernel 会保持 HeavyWork 隔离，并设置进程级 `restartRequired`；迟到任务结束后本进程仍不允许再次运行，界面明确要求重启。
- 进入 `.persisting` 后取消按钮隐藏，Store 拒绝迟到取消。结果先保存为不可进入正式成绩的 provisional 记录，再用一次原子替换升级。
- 原子替换有相同的持久化超时。升级前同步持久化目标 record ID 的“未确认”标记；只有升级在时限内返回成功才移除。若升级迟到，即使成功记录最终落盘，当前进程保持 `restartRequired`，下一次启动也会过滤该 record ID，不能冒充正式成绩。
- fault fixture 覆盖：原子 writer 失败时原文件字节不变；迟到替换失败后 provisional 记录跨 reload 仍非正式；替换永久阻塞时 Store 有界返回、禁止本进程重试，迟到 success 落盘后新的 Store 仍看不到该记录。
- 当前发布前专项为 **47 项执行、0 failures**；此前完整性能过滤为 **394 项执行、5 项显式实机/校准 opt-in 跳过、0 failures**。完整树和最终 Release 构建以本轮后续最终报告为准。
