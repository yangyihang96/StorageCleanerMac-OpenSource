# 存储清理助手 v1.4.0 设计规格

日期：2026-07-15

状态：用户已授权自主选择方案并完成开发、验证与发布

目标版本：1.4.0

目标系统：macOS 14 及以上，重点验证 macOS 26

## 1. 产品目标

v1.4.0 是一次中等规模功能升级，而不是补丁版本。它需要同时完成以下目标：

1. 增加一个聚合、可操作的“电脑健康”中心。
2. 增加磁盘状态、容量趋势、备份保护、系统稳定性、电池健康、电源模式引导和网络测速。
3. 在“垃圾文件检索”中增加显式触发的“敏感隐私内容清理”。
4. 将菜单栏详细模式升级为信息密度接近 iStat Menus 的模块化小窗，同时保持精简模式。
5. 修复面板模式选项悬停消失、快速切页卡顿、启动同步读取和重复刷新等问题。
6. 清理重复控件与重复代码，不增加没有实际用途的设置。
7. 完成真实运行、性能、打包、安装、GitHub Release、Sparkle appcast 和旧版更新验证。

## 2. 核心原则

- 只展示真实可读取的数据；无法读取与异常必须分开。
- 只提供有明确结果的操作；不为堆信息增加页面。
- 菜单栏每秒刷新只能读取轻量实时指标或缓存，不能启动重任务。
- 网络测速、隐私扫描、完整健康刷新都必须由用户显式触发或低频缓存。
- 不使用私有 macOS API、不请求管理员权限、不直接修改充电上限。
- 不直接修改浏览器历史数据库；敏感历史通过浏览器原生入口清理。
- 浏览域名、URL、搜索词和页面标题不得进入日志、通知、清理历史或崩溃报告。
- 所有 shell、SQLite、文件枚举和网络任务都必须可取消、可超时并脱离主线程。
- 保持字体字号、数字基线、等宽数字以及网络上下行颜色一致。

## 3. 信息架构

主导航采用以下结构：

1. 智能扫描
2. 电脑健康
3. 存储与清理
4. 系统工具
5. 设置

只为 `ReviewFilter` 新增一个顶层 `healthHub`。电脑健康内部使用局部 section 状态，不为每个健康模块增加侧边栏路由。

“敏感隐私内容清理”留在“垃圾文件检索”页面，不新增独立侧边栏入口，不进入自动体检和健康评分。

## 4. 电脑健康中心

### 4.1 页面结构

电脑健康首页由六张模块卡片和一个“需要处理”区域组成：

1. 磁盘状态
2. 容量趋势
3. 备份保护
4. 系统稳定性
5. 电池健康与电源模式
6. 网络测速

卡片只展示摘要、最后更新时间和一个主要动作。详细内容在同页展开，避免新增多层导航。

统一状态模型：

- `healthy`：有可靠数据且没有需要处理的问题。
- `attention`：值得关注但不紧急。
- `actionRequired`：有明确、可执行的处理建议。
- `unavailable`：权限、硬件或系统没有提供可靠数据。

`unavailable` 绝不能被映射成 `healthy`。

### 4.2 磁盘状态

展示：

- 启动卷文件系统与容量。
- 可用容量和容量压力。
- 内置/外置、固态介质状态。
- SMART 状态。
- TRIM 支持状态。
- FileVault 状态（系统提供时）。

数据来源：

- `/usr/sbin/diskutil info -plist /`
- `/usr/sbin/system_profiler -json -detailLevel mini -timeout 5 SPNVMeDataType`
- 现有 `StorageCapacityService`

约束：

- SMART `Verified` 只表示系统报告通过，不转换成虚假寿命百分比。
- 不在后台运行 `diskutil verifyVolume`、磁盘急救或 `fsck_apfs`。
- 不显示或持久化磁盘序列号。
- 无法读取时显示“系统未提供”，不显示“正常”。

### 4.3 容量趋势

- 每天最多记录一次启动卷容量快照。
- 保留最近 90 个有效数据点。
- 只保存时间、总容量和可用容量，不保存路径或文件名。
- 显示 7 日/30 日可用容量变化。
- 少于 7 个有效日样本时不预测“几天后满盘”。
- 总容量变化超过 5% 时断开旧趋势，避免更换磁盘或 APFS 容器变化造成误判。

### 4.4 备份保护

展示状态必须拆开：

- 是否配置 Time Machine 目标。
- 当前是否正在备份。
- 最近本地快照。
- 最近完整备份（只有可靠读取到时）。
- 目标暂时不可访问或权限不足。

数据来源使用固定绝对路径调用 `tmutil`，每个调用均有短超时。目标 URL、ID 和网络地址不得写日志或持久化。

操作只允许：

- 打开 Time Machine 设置。
- 打开系统备份位置（系统允许时）。

不在应用内启动、停止或删除备份。

### 4.5 系统稳定性

- 限量读取最近 7/30 天的 `.ips`、`.crash`、`.hang`、`.spin` 和明确的 panic 报告。
- 只读取文件名、修改时间和报告头部的应用名/类型。
- 不读取或展示调用栈、启动参数、用户名路径、镜像列表。
- 不上传报告，不运行 `log show`、`spindump` 等重命令。
- 最多检查 500 个文件，每文件最多读取头部 64 KiB，总读取量和总耗时设硬上限。
- 操作只提供“在访达中查看诊断报告”。

### 4.6 电池健康与电源模式

采用“安全引导模式”。

展示：

- 当前电量、充电状态、供电来源和剩余时间。
- 最大容量、循环次数和系统健康状态。
- 当前低电量/自动/高电量模式（只有系统可靠提供时）。
- 电池供电和电源适配器的模式分别显示。

推荐算法：

- 系统 condition 为第一优先级。
- 最大容量只有单位和值可信时才显示百分比。
- 循环次数作为背景信息，不用单一阈值制造恐慌。
- 80% 左右暂停充电且系统正在执行优化充电时，解释为正常保护行为。
- 电池电量较低时建议用户考虑低电量模式。
- 接电日常使用优先建议自动模式。
- 高电量模式只在机型支持且用户有持续重负载需求时出现建议。

操作流程：

1. 用户点击“调整电池设置”。
2. 应用打开系统电池设置，不请求管理员权限。
3. 用户返回应用后，应用重新读取状态。
4. 只有重新读取到变化才显示“已验证生效”。

应用不使用 `pmset` 修改模式，不直接控制优化充电或充电上限。

### 4.7 网络测速

使用系统 `/usr/bin/networkQuality -c -M 20`，而不是自建测速服务器。

展示：

- 下载 Mbps。
- 上传 Mbps。
- Responsiveness（RPM）。
- 空闲延迟。
- 网络接口。
- 测试时间。

交互：

- 仅用户点击后运行。
- 首次明确提示会使用网络流量。
- 同一时间只允许一个测试。
- 显示进度、取消和硬超时。
- 取消时按 SIGINT、短等待、SIGTERM 的顺序结束子进程。
- 失败、离线、取消和超时不保留半成品。
- 保存的只能是最后一次成功摘要，并明确标记时间，不能冒充实时结果。

## 5. 敏感隐私内容清理

### 5.1 入口与触发

在“垃圾文件检索”页面增加一张“敏感隐私内容清理”卡片。

它必须由用户显式点击启动，不参与：

- 应用启动。
- 智能体检。
- 标准垃圾扫描。
- 菜单栏后台刷新。
- 定时任务。
- 电脑健康评分。

### 5.2 扫描范围

首版支持：

- Safari。
- Chrome 全部 Profile。
- Edge 全部 Profile。
- Firefox 全部 Profile。

扫描内容：

- 浏览历史。
- 下载记录元数据，但不删除已下载文件。
- 浏览器缓存。
- Cookie/网站数据只做独立摘要和原生清理引导。

每个浏览器使用独立 adapter。读取 SQLite 时使用短生命周期一致性快照，临时目录权限为 `0700`、文件权限为 `0600`，任务结束或下次启动时清除遗留快照。

### 5.3 敏感站点分类

- 仅规范化和聚合 hostname，不读取页面正文。
- 不使用 URL 路径、查询参数和页面标题进行粗暴关键词判断。
- 高置信度来自离线、版本化、可审计的精确域名规则。
- 中低置信度只允许匹配 hostname 标签边界，永不自动勾选。
- 支持 IDN/Punycode、大小写、尾点和严格子域名边界。
- 用户手动标记仅在本次会话生效，首版不持久化私密域名清单。
- 所有结果统一称为“可能敏感”，不得断言用户访问了某类内容。

结果默认显示：

- 浏览器与 Profile。
- 脱敏域名。
- 访问条数。
- 最近访问日期。
- 匹配原因和置信度。

完整域名只能由用户在本次会话中临时展开。完整 URL、标题、搜索词和查询参数永不显示、导出或记录。

### 5.4 清理边界

采用“安全混合模式”：

- 缓存：浏览器完全退出后，复用现有移入废纸篓流程。
- 浏览历史：打开对应浏览器的官方历史管理入口，由浏览器执行删除。
- 下载记录：打开浏览器原生历史/下载管理入口，不删除磁盘上的下载文件。
- Cookie/网站数据：独立入口、默认关闭、二次确认，并提示可能退出登录。
- 不直接修改 `History.db`、`Cookies`、`places.sqlite`。
- 绝不删除整个历史数据库或 Firefox Profile。
- 不自动强制退出浏览器。
- 删除前必须提示同步可能影响其他设备。

结果状态必须区分：未安装、无权限、数据库忙、未知结构、损坏、超时、取消、没有发现。

## 6. 菜单栏小窗

### 6.1 模式

- 精简模式：保留当前双标签紧凑小窗。
- 详细模式：采用模块化卡片、图表和同一套视觉原语，信息密度参考 iStat Menus。

“面板模式”不再使用容易在悬停时消失的嵌套菜单。齿轮按钮打开小窗内固定设置面板，使用直接可点击的“精简 / 详细”分段控件；选择后立即持久化并实际切换。

### 6.2 详细模块

1. 综合
2. CPU 与 GPU
3. 内存
4. 磁盘
5. 网络
6. 传感器
7. 电源

CPU 与 GPU：

- CPU 总使用率、用户/系统占比、核心负载。
- 频率、负载、运行时间。
- 电压、电流、功耗只有系统可靠提供时显示。
- GPU 使用率、显存、温度、频率等可用数据。
- 可操作的高占用应用列表。

内存：

- 压力、App、联动、压缩、空闲、交换空间。
- 可关闭应用列表，不展示不可关闭的系统进程。

磁盘：

- 可用空间、容量压力、SMART、7 日变化和备份摘要。

网络：

- 实时上下行曲线。
- 上次手动测速结果和时间。

传感器：

- CPU/GPU 温度。
- 每个可读取风扇的真实 RPM。
- 不可用字段自动隐藏。

电源：

- 电量、充电状态、最大容量、循环次数和电源模式。

综合页面只放关键摘要和需要处理的操作，不重复所有子页面内容。

### 6.3 视觉与刷新

- 统一使用 App 现有设计 token、圆角、材质和系统动态颜色。
- 数值统一使用等宽数字、相同基线和字重。
- 上传保持蓝色，下载保持粉色，所有页面一致。
- 图表动画只作用于新增采样，不对整个页面树做切换动画。
- 实时 CPU/网络保持 1 秒。
- 电池电量 15–30 秒。
- 容量 60 秒。
- SMART/Time Machine 10 分钟或手动。
- 稳定性和静态电池健康 30 分钟或手动。
- 测速和隐私扫描仅手动。

## 7. 架构与状态隔离

新增独立状态域：

- `ComputerHealthStore`
- `NetworkSpeedTestStore`
- `PrivacyHistoryStore`

新增服务：

- `DiskHealthService`
- `CapacityHistoryService`
- `TimeMachineStatusService`
- `StabilityReportService`
- `BatteryHealthService`
- `NetworkSpeedTestService`
- `PrivacyHistoryScanner`
- 浏览器 adapter 与原生清理路由服务

不得继续把这些状态加入已有的大型 `ScanStore`。

所有重服务使用 actor 或后台任务，并统一输出：

- `available`
- `partial`
- `permissionDenied`
- `timedOut`
- `cancelled`
- `unavailable`

菜单栏只读取 `ComputerHealthStore` 的缓存摘要。

## 8. 卡死、启动与重复代码治理

实施新功能前先完成以下高优先级修复：

1. 能耗、卸载和更新列表的 filter/sort/max 改为每个快照只计算一次。
2. 移除 SwiftUI `body` 中的同步 `fileExists` 和 `NSWorkspace.icon(forFile:)`。
3. 使用异步 `CachedAppIconView`，首屏显示占位图标。
4. 移除详细小窗内容层和 ScrollView 层的双重 `.id(selectedSection)`。
5. 将整页 transition 改为选择指示器和局部采样动画。
6. 扫描历史和清理历史改为启动后后台解码并一次回填。
7. 合并 `refreshMenuBarMonitor` 和 `refreshMenuBarLiveStatus` 的重复状态机。
8. 简约/详细小窗共享容量、电池和健康缓存，不重复采样。
9. 真实运行确认侧边栏按钮，只保留系统标准切换入口，移除重复按钮。
10. 将超大菜单栏文件拆成独立 section view 和共享视觉组件，但不强行合并主窗口与小窗布局。

## 9. 测试与验收

### 9.1 自动化测试

- 每个新 Service 使用 fixture 覆盖正常、缺字段、损坏、权限、超时和取消。
- 网络测速覆盖离线、VPN、取消、坏 JSON、重复点击和超时。
- 隐私扫描全部使用合成 SQLite 数据库，覆盖多 Profile、WAL、锁、损坏、未知 schema、100 万条记录、IDN 和误报样本。
- 验证日志、UserDefaults、通知、清理历史和崩溃报告中没有域名或 URL。
- 验证 Firefox 书签和真实下载文件从不进入删除路径。

### 9.2 真实运行

- 打开 `/Applications/存储清理助手.app`，确认真实菜单栏与小窗，不依赖旧截图。
- 主窗口连续切页 120 次。
- 详细小窗连续切换 80 次。
- 停止操作后 2 秒内 CPU 回落到常驻水平。
- 菜单隐藏状态采样 60 秒，不高于现有约 1–2% CPU 基线。
- 冷启动至少执行 10 次并比较中位数。
- 使用 Time Profiler/signpost 检查主线程排序、图标读取和 SwiftUI 重建。
- 验证风扇 RPM、CPU 频率/电压等字段只在真实可用时显示。
- 隐私页面真实截图只能使用空状态或合成演示数据。
- 重点验证 macOS 26，兼容 macOS 14 及以上。
