# Storage Cleaner Mac v1.4.0 Privacy Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an explicit, local-only privacy scan that aggregates browser traces and possible sensitive sites without persisting URLs, then routes history/site-data removal through browser-native controls while allowing safe cache trashing.

**Architecture:** A dedicated `PrivacyHistoryStore` owns one cancellable scan and never participates in standard scanning or startup. Browser adapters enumerate profiles and stream URL rows from short-lived SQLite backup snapshots into a hostname aggregator; a conservative offline classifier marks only possible matches. Cleanup uses browser-native history/site-data UI, except regenerable cache paths that reuse the existing trash service after the browser is closed.

**Tech Stack:** Swift 6, SwiftUI, Foundation, SQLite3, AppKit NSWorkspace, XCTest with synthetic SQLite databases.

**Test fixture convention:** Every `.fixture` scanner or synthetic database helper named below is implemented privately inside the relevant test file. Tests create only temporary fake browser profiles and never depend on or inspect the user's real browser history.

- [ ] **Step 3: Implement secure snapshots and streaming queries**

Use SQLite Online Backup API into a unique temporary directory with directory mode `0700` and file mode `0600`. Retry `BUSY/LOCKED` only within a two-second profile deadline. Install `sqlite3_progress_handler` and call `sqlite3_interrupt` on task cancellation.

Each adapter verifies required tables/columns before querying. Stream each URL through `URLComponents`, normalize only the hostname, aggregate counts and last-visit time, then discard the full URL immediately. Cap concurrent profiles at two, aggregate domains at a bounded count, and cap the whole scan at 15 seconds.

- [ ] **Step 3: Implement auditable local rules**

High confidence matches the complete terminal suffix labels `adult`, `porn`, `sex`, and `xxx`. Medium confidence matches a conservative set of complete hostname labels; it never searches URL paths, queries or titles. Normalize IDN/Punycode, case and trailing dots, and compare label boundaries from the registrable-domain end. User session marks are exact normalized domains and are not persisted.

```swift
struct SensitiveDomainMatch: Equatable, Sendable {
    enum Confidence: String, Sendable { case high, medium, userMarked }
    let confidence: Confidence
    let reason: String
}
```

No rule initiates network, DNS or content requests. No match is selected automatically.
