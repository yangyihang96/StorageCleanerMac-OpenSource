### 2.1 下载前复核（2026-08-05）

官网更新进入暂存下载前，`stageOne` 现在先复用 `preflight` 重新读取磁盘 Bundle 的签名身份和原版本，再重跑 automatic eligibility（仅把“正在运行/需正常退出”视为可等待条件），确认任务 Provider 仍与注册表一致，并按 `ApplicationUpdateDiskSpacePolicy` 检查临时卷和应用目录的可用空间。任一项目的身份、版本、资格或空间复核失败时，不调用该项目的 `prepareUpdate`/`stage`；同一两项批次中的合法兄弟项目仍会继续并行暂存。`execute` 保留安装前的第二次复核，以覆盖下载后到安装前的 TOCTOU 窗口。

当前磁盘空间检查仍按项目独立 fail closed；现有容量注入没有提供可安全预留/扣减的批次租约，因此没有伪造同一两项并发下载的总需求汇总。若后续要支持批量保守汇总，应先为临时卷容量增加明确的预留语义，再扩展 `ApplicationUpdateDiskSpacePolicy` 和批次协调，不以重复读取同一可用字节数代替预留。

当前“一键更新”会纳入可立即执行的严格 automatic 项，以及“仅因为当前正在运行/需正常退出而阻塞”的严格 automatic 项。后者会进入 `waitingForQuit`；构建计划时会先临时清除这两个瞬态标志，再重跑同一个严格资格判定，因此 duplicate、宿主自身、需交互/授权、手动和未验证来源不会借由 `requiresQuit` 绕过安全门。只有精确匹配 `mas outdated`、产品 ID、路径、版本、receipt 和签名身份的 App Store 项可进入 automatic；其他 App Store 项仍留在公开 App Store 入口。Coordinator 观察到正常退出后还会重新核对点击时身份、版本和来源，才允许回到 queued。

仓库中保留的 `ScanHeavyWorkService.runAppUpdates` 与 `AppUpdateService` 旧批处理辅助路径当前没有被 `ScanStore`、应用更新视图或 App 入口调用；它们仅为兼容测试/旧调用保留，并不构成生产“一键更新”证据。该旧路径仍可能提供 Homebrew 文本命令备用操作，因此不能作为自动更新成功或安全闭环的证明。

只有用户明确确认的批量 session 才会对运行中的严格 automatic 目标调用系统正常退出请求；匹配同时要求精确 Bundle ID 与保留大小写、解析符号链接后的精确应用路径。代码不调用 `forceTerminate`、`kill` 或 shell，也不自动重启第三方应用；取消、自动策略、恢复和监控路径都没有这份确认令牌。相关 Coordinator 定向回归 **32/32 通过**，但本轮没有实际退出或更新任何用户应用。

结构化 recipe 当前包含需求中的主要安全字段：应用 ID、显示名、当前/目标版本、Provider、可执行文件 URL、参数、工作目录、环境 allowlist、授权/退出要求、下载 URL、预期 Bundle ID / Team ID / 版本、SHA-256、验证步骤和回滚计划。代码没有把任意用户字符串交给 `sh -c`。

## 4. 已由联合测试覆盖的关键合同

- 执行前资格、磁盘版本、签名身份和空间复核；
