# StorageCleanerMac 1.9.12 五轮性能审阅与验证

日期：2026-08-28
范围：应用响应、小窗响应、后台内存、后台唤醒与持久化 I/O
原则：复用现有 Store、Monitor、Panel、Timer 与 Helper，不改变清理和硬件控制安全边界。

## 基线

- 旧测试版 Build：`20260827162648`
- 主窗口与小窗关闭后的 `vmmap` 物理占用：约 135.0 MB
- 同状态六次 2 秒采样：CPU 为 `0.0 / 1.2 / 0.0 / 0.0 / 0.0 / 0.0%`
- `heap` 中四个空槽遥测数组合计：20,381,696 bytes
- 线程数：4–5

## 第一轮：遥测历史内存

- 问题：28 天分钟历史在初始化时按最大容量创建 Optional 空槽，即使没有数据也会立即占用约 20 MB。
- 修改：环形缓冲区按真实样本数增长，达到容量后才覆盖旧槽；清空时真正释放存储。
- 保护：覆盖、移除、头部回绕和 40,323 容量空缓冲均有测试。

## 第二轮：小窗与后台刷新

- 问题：小窗隐藏后仍使用较短固定刷新间隔；打开小窗、切换菜单栏指标或风扇模式时，刷新节奏不能立即重算。
- 修改：按小窗可见性、菜单栏显示项目、低电量模式和风扇控制状态自适应刷新。
- 结果：默认隐藏状态 30 秒；需要常驻状态的指标按 5/15 秒；小窗可见时保持 1/2/5 秒；手动或曲线风扇控制保持 2 秒安全回读，并在打开和模式变化时立即刷新。

## 第三轮：主界面批量操作

- 问题：扫描结果整组选择会对每个 ID 再遍历全部候选项，数据量大时退化为平方级工作量。
- 修改：一次创建请求 ID 集合、一次遍历会话候选项，再批量合并或扣除选择集合。
- 结果：批量选择由近似 O(n×m) 降为 O(n+m)，未知、过期和不可选择 ID 仍会被拒绝。

## 第四轮：长期后台内存与磁盘写入

- 问题一：小窗隐藏后永久保留完整 SwiftUI hosting tree。
- 修改一：保留 60 秒快速重开窗口；持续闲置后由现有 MenuBarStatusController 释放同一个 PanelSession，不创建第二套协调器或计时器。
- 问题二：能耗累计每 30 秒采样一次，同时每次都写入磁盘。
- 修改二：计算频率不变，普通持久化合并为最多每 5 分钟一次；睡眠和退出仍强制保存，写入失败不会推进节流时间。

## 第五轮：遥测热路径复审

- 问题：每追加一个遥测点会连续运行两遍相同历史压缩；过期分钟点逐个删除。
- 修改：每次追加仅压缩一次；过期分钟点计数后批量淘汰。
- 保护：完整 SystemMonitorServiceTests 历史、时间倒退、跨 epoch、28 天保留和图表时间戳测试通过。
